# Localization

Kavka's shell speaks six languages. Its cluster views speak one. This document
says exactly where the line is, how the framework works, and what to do if you
want to move the line or fix what is on the wrong side of it.

**Status:** shipping. English is complete and reviewed. German, Spanish,
French, Brazilian Portuguese and Japanese are **machine translations that no
native speaker has read**, and the app says so, in the language being offered,
next to the language picker. That honesty is not a disclaimer — it is the
feature. A support engineer deciding whether to trust a translated sentence
about a prod cluster is entitled to know who wrote it.

---

## 1. The coverage boundary, stated plainly

**Translated — the shell.** Six files, 243 message keys:

| Surface | File |
|---|---|
| App shell: status bar, empty states, first-run screen, global errors | `apps/desktop/src/App.tsx` |
| Sidebar: cluster list, connection states, footer | `apps/desktop/src/Sidebar.tsx` |
| Command palette: every row, every keyword, the empty state | `apps/desktop/src/Palette.tsx` |
| About dialog's own text and the language picker — **not** the two sections it hosts, below | `apps/desktop/src/AboutDialog.tsx` |
| Export / import connections dialog | `apps/desktop/src/ImportExportDialog.tsx` |
| The connection form, all of it — labels, hints, validation, confirmations | `apps/desktop/src/ProfileEditor.tsx` |

**Not translated — everything a connected cluster shows you.** Topics, consumer
groups, the message browser and inspector, search and CEL, SQL, produce,
monitoring and charts, ACLs, quotas, schemas, Connect, partition operations,
alerts, masking, the copy wizard, the offset-reset and migrate modals, the
playground, and the glossary in `Glossary.tsx`. **These are English in every
locale.** They are the next extraction target, and they are roughly four times
the volume of what is done.

**Also not translated, on purpose:**

- **`McpSection.tsx` and `DiagnosticsSection.tsx`** — the two panels the About
  dialog renders beneath its own text. The dialog around them is translated and
  they are not, which is the one place in the app where the seam sits *inside* a
  single screen, so it is stated here rather than left to be found. They are
  long-form technical prose — an MCP config snippet, two environment-variable
  gates, a list of what a log line contains and what it never contains — and
  they are the two surfaces in Kavka where a mistranslated sentence changes what
  somebody believes about their own privacy or about what an AI assistant is
  allowed to do with their brokers. A machine translation nobody has read is the
  wrong instrument for both. They go in the same wave as `errors.ts` and the deep
  views, and a *reviewed* locale is the right time to move them, not before.
- **`errors.ts`.** The error library (DESIGN.md §7) is a pure function shared
  by every renderer of an error, and it is the single highest-value thing left
  to translate — but it is one file with one owner and a table of thirteen
  causes, and half-doing it (translating the banner's fallback sentence while
  the classified titles stay English) reads worse than not doing it. It goes
  in the same wave as the deep views.
- **`monitoring.ts`'s `formatSpan`.** Same reason. `ProfileEditor` needed two
  spans inside a translated paragraph, so it formats those two itself from
  `unit.*` keys (`spanText`); the thresholds are copied from `formatSpan` and
  the comment there says to change both or neither.
- **The environment tokens `dev` / `staging` / `prod`.** These are the same
  three strings as the `data-env` attribute, the window title and the literal
  `PROD` the wire grows in forced-colors mode (DESIGN.md §6, §10). Prod is a
  nine-layer guardrail; a chip that says one thing while the wire says another
  is two signals where the design specifies one.
- **Machine literals.** Bootstrap hosts, PEM headers, JSON skeletons, AWS
  regions, URLs, `~/.aws/config`, the repository address. DESIGN.md §4 already
  calls these "a literal that came out of Kafka and could be pasted into a
  `kafka-topics.sh` command"; a literal that changes by locale is not a
  literal. Example *names* (`orders — local`, `orders connect`) **are** in the
  catalogs, so a locale can adapt them — the machine translations leave them
  as-is.
- **Key names.** `⌘K`, `Ctrl`, `Esc`, `⏎`.

**What a user in `de` actually sees:** a fully German sidebar, palette,
dialogs and connection form, then English the moment they connect. That is a
real seam and this document exists partly so nobody is surprised by it. It is
the right seam to have chosen: the shell is where a novice spends their first
ten minutes and where every destructive confirmation lives.

## 2. The framework

Three files, no dependencies:

```
apps/desktop/src/i18n/
  format.ts        the ICU-lite grammar. Pure — strings in, parts out.
  index.ts         locale detection, persistence, lookup, fallback, hooks.
  catalogs/
    en.ts          the source. Complete by definition; every other catalog
                   is typed against its keys.
    de.ts es.ts fr.ts ja.ts pt-BR.ts
```

### Why hand-rolled

The product's pitch is a single binary that runs entirely on your machine.
Pulling a message-format compiler and a polyfill chain into the bundle to do
what `Intl.PluralRules` and `Intl.NumberFormat` already do is not a trade this
app should make. The grammar accepted is a strict **subset of ICU**, so a
catalog written for Kavka can be handed to a real ICU toolchain later without a
rewrite. That direction is the one that matters.

### Why `.ts` catalogs and not `.json`

Two reasons, both load-bearing:

1. **JSON has no comments.** Every machine-translated catalog is headed by a
   block saying it is machine-translated and inviting review. A `"_note"` key
   is not a comment; it is a message that would need translating.
2. **`en.ts` exports `MessageKey = keyof typeof en`.** Every call site is
   `t("sidebar.title")` with compile-time checking, a typo is a build error,
   and a translation file cannot invent a key that nothing reads. `Catalog` is
   `Partial<Record<MessageKey, string>>`, so a translation is *allowed* to be
   short — it falls back — while still being unable to be *wrong*.

The files contain nothing but a JSON-shaped object literal. They are JSON
modules in every sense except the file extension.

### Using it

```tsx
const { t, tx, locale, setLocale } = useI18n();

t("sidebar.title")                          // "Clusters"
t("palette.goTo", { name: p.name })         // "Go to orders — local"
t("editor.err.sampler", { seconds: 5 })     // plural-correct in every locale

tx("app.firstRun.example", {                // a ReactNode
  example: <code>kafka-1.internal:9092</code>,
  local: <code>localhost:9092</code>,
})
```

- **`t` returns a string.** It is what `title`, `placeholder`, `aria-label` and
  any plain text node take.
- **`tx` returns a `ReactNode`.** It is what a sentence containing a `<code>`
  or a `<strong>` takes. The element goes in as a **parameter**, so the
  translator sees one whole sentence with named slots and never sees markup —
  and never has to preserve an English word order that a string-concatenation
  approach would have frozen.
- **`t(key)` outside a component** is exported from `i18n/index.ts` for
  non-React callers. It reads the current locale at call time.

### The one way to get this wrong

`useI18n()` returns `t`/`tx` **memoized on the locale**. That makes them stable
within a language and a new identity the moment the language changes, which in
turn makes this correct:

```tsx
const actions = useMemo(() => [...], [profiles, connections, t]);
//                                                            ^ required
```

**A `useMemo` or `useCallback` that closes over `t` must list it.** Omit it and
that component's labels freeze in the previous language when the user switches.
`Palette`'s action list, `App`'s contextual commands and `ProfileEditor`'s
`validate` all list it; copy that.

### Detection and persistence

1. `localStorage["kavka.locale"]`, if it holds a known code. A choice made once
   survives the restart.
2. Otherwise walk `navigator.languages` in order, taking an **exact** tag first
   (`pt-BR`), then the **primary subtag** (`de-AT` → `de`, `en-GB` → `en`,
   `pt-PT` → `pt-BR`).
3. Otherwise `en`.

`pt-PT → pt-BR` is a deliberate approximation: Brazilian is the only
Portuguese catalog that exists, and a European Portuguese speaker reading
Brazilian is better served than one reading English. The picker is one click
away either way.

`setLocale` persists, sets `document.documentElement.lang` (screen-reader
pronunciation, `:lang()`, hyphenation) and notifies subscribers through
`useSyncExternalStore`. `localStorage` access is wrapped — a browser with
storage disabled loses the preference, not the app.

### Fallback and dev warnings

A missing key falls back to English and **warns once**, in dev only:

```
[i18n] de has no "editor.foo" — using English
```

At startup, dev also prints a per-catalog completeness line naming the first
few missing keys. A key missing from *every* catalog renders as the key itself
rather than as blank — visible, not silent.

Malformed messages never throw. An unbalanced `{`, an unknown argument type, a
plural with no matching arm: each degrades to text and warns. A translation is
data a stranger wrote; it must not be able to blank a dialog.

## 3. The grammar

Everything `format.ts` accepts, in full. If it is not here, it is not
supported.

| Construct | Meaning |
|---|---|
| `{name}` | Interpolation. A number is grouped with `Intl.NumberFormat` for the active locale (DESIGN.md §7 rule 5); a React element passed through `tx` survives intact. |
| `{name, number}` | The same, said out loud. |
| `{n, plural, one {# thing} other {# things}}` | CLDR categories via `Intl.PluralRules`: `zero one two few many other`. `#` is the number, grouped. |
| `{n, plural, =0 {none} other {# things}}` | An exact selector wins over the category. |
| `{kind, select, prod {…} other {…}}` | Exact string match with an `other` arm. |
| `{{` and `}}` | A literal `{` / `}`. |

**There is no apostrophe escaping.** Real ICU treats `'` as a quote character;
this product's voice is full of *"Kavka couldn't"*, *"you'll"* and
*"doesn't"*. A grammar that mangles the house style is the wrong grammar. If
you port these catalogs to a real ICU tool one day, that is the one rule to
re-check.

Plural categories differ by language and that is the point:

- German, Spanish: `one` / `other`.
- French, Portuguese: `one` covers **0 and 1**; then `other`.
- Japanese: `other` only. There is no `one` arm to add.

## 4. Fixing a translation

**This is the highest-value contribution to Kavka right now, and it needs no
build, no tooling and no account.**

1. Open `apps/desktop/src/i18n/catalogs/<code>.ts`.
2. Fix the sentences that are wrong. Fix one, fix ten, fix the file.
3. Open a pull request. Say in it which locale you speak.

Rules, all of them:

- **Keep the `{placeholders}`.** They are values Kavka substitutes. A renamed
  or dropped slot silently deletes a topic name, an address or a count from
  the sentence. If a slot makes no sense where the English put it, move it —
  that is the whole reason it is a slot.
- **Keep `#` inside plural arms.** It is the number.
- **Add the plural arms your language needs**, and delete the ones it does not.
  Missing arms fall through to `other`.
- **`*.kw` keys are search vocabulary, not prose.** They feed the command
  palette's matching. **Keep the English words and append yours** — DESIGN.md
  §5.9's "matching is bilingual" means an operator who learned Kafka in English
  must still be able to type `bootstrap` and `broker` in a German UI.
- **Follow DESIGN.md §7 in your language.** Sentence case. The verb survives
  the whole flow (`Connect` → `Connecting…` → `Connected to …`). Errors state
  what happened and then the next click. No apologies, no exclamation marks, no
  "Oops".
- **Delete rather than guess.** A key you remove falls back to English, which
  is correct English. A key you guess at is wrong in your language and nobody
  will catch it.
- **Watch the length.** DESIGN.md §5.5 budgets ~40% growth for translated
  toolbar labels; German usually spends it and Japanese usually runs shorter,
  which is its own layout problem. Sidebar rows, palette rows and status-bar
  items are the tight ones.
- **When the file is genuinely reviewed**, flip `machine: false` for that
  locale in `LOCALES` in `apps/desktop/src/i18n/index.ts`, delete the "machine
  translation" header block, and say in the PR that you are a native speaker.
  That flag is what turns off the warning under the language picker, and it is
  the only thing that should.

Then run the gate: `npx tsc --noEmit && npm run build` from `apps/desktop`.

## 5. Adding a language

Say you are adding Italian.

1. **Copy `en.ts` to `catalogs/it.ts`.** Change the const name and the
   `export default`, and give it the machine-translation header if that is
   what it is. It imports `type { Catalog } from "./en"`, which is what makes
   a typo a build error.
2. **Translate.** A partial catalog is fine and shippable — everything you
   have not done falls back to English, and the dev console tells you how many
   keys are left.
3. **Register it** in `apps/desktop/src/i18n/index.ts`: add `"it"` to the
   `Locale` union, an entry to `LOCALES` (code, endonym — the language's own
   name for itself, never translated — English name, and `machine`), the import,
   and the entry in `CATALOGS`. Four lines and an import; TypeScript refuses
   the build until all four are there.
4. **Check the plural rules** your language actually uses:
   `new Intl.PluralRules("it").select(n)` for `n` in 0, 1, 2, 5, 100. Write
   only the arms it returns, plus `other`.
5. **Run the gate** and switch to it in the About dialog.

A regional variant (`pt-PT`, `es-MX`, `zh-Hant`) is a **new entry**, not an
edit of the one that already exists. Detection tries the exact tag before the
primary subtag, so adding `pt-PT` automatically takes `pt-PT` users off
`pt-BR` with no other change.

## 6. Where the strings live

243 keys, in eight namespaces:

| Namespace | Keys | What |
|---|---:|---|
| `editor.*` | 115 | The connection form: labels, hints, sign-in methods, validation |
| `transfer.*` | 36 | Export / import dialog, including the import report's plurals |
| `palette.*` | 31 | Command palette rows, contexts and search keywords |
| `app.*` | 25 | Status bar, empty states, first-run, contextual commands |
| `common.*` | 12 | Strings more than one surface uses |
| `sidebar.*` | 11 | Cluster list and connection states |
| `about.*` | 9 | About dialog and the language picker |
| `unit.*` | 4 | Second / minute / hour / day, plural-correct |

Every catalog is complete: **243 / 243 in all six languages**, verified by key
parity, placeholder parity (every `{slot}` in English present in every
translation, and none invented), `#` survival inside plural arms, and a format
pass over every message in every locale that must produce no warnings and leave
no unsubstituted braces.

Adding a string is: add the key to `en.ts`, use it, ship. The other five
catalogs do not block you — they fall back and the dev console lists the debt.
