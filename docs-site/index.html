A Kafka client that is
actually free.

Kavka is a desktop client for Apache Kafka on macOS and Windows. Every feature is in the free app — no tiers, no licence keys, no seat count, no server to run. Personal use, commercial use, a hundred engineers: the same build.

It fills the gap left by Conduktor Desktop's retirement and Offset Explorer's stagnation: a small, native-feeling client with no JVM and no Docker of its own.

Download Source on GitHub

Connection passwords go to the operating system's keychain. Nothing about your clusters leaves the machine — there is no telemetry endpoint in the app.

01

Everything, in the free app

There is no paid tier to compare this against, so the list below is simply the list. It mirrors the repository's README, which mirrors docs/FEATURES.md — one specification, three places it is quoted.

Connect

The whole auth matrix

PLAINTEXT, TLS and mTLS from PEM files with no keystore conversion, SASL PLAIN and SCRAM, OAUTHBEARER/OIDC, AWS MSK IAM, Kerberos. Secrets go to the OS keychain; per-connection read-only mode is enforced in the core, not the UI.

Browse

Search a whole topic

Streaming search across every partition with raw-byte prefilters and CEL push-down, progressive results and cancellation. It never silently truncates: it says what it scanned, what it could not evaluate and where it stopped.

Decode

Serdes that just work

Avro, Protobuf and JSON Schema through Schema Registry (Confluent, Apicurio, Glue), plus XML, MessagePack, CBOR and hex. Every message shows the subject, version and id it was decoded with — or says plainly that nothing matched.

Operate

The whole admin surface

Consumer-group lag and every offset-reset mode, ACLs, client quotas, partition reassignment with throttles, preferred leader election, broker configs, the KRaft quorum, Kafka Connect CRUD and Schema Registry management.

Monitor

Lag history that survives restarts

A local sampler writes lag to an embedded store, so the charts cover last week rather than since you opened the window. Alert rules fire OS notifications and webhooks. Kafka Streams topologies render; KIP-932 share groups are visible.

Power

SQL, replay and diff

SQL over a bounded scan of a topic. Cross-cluster copy and replay with transforms, config diff between environments, consumer-offset migration and DLQ workflows. Custom decoders as sandboxed WebAssembly plugins.

Guardrails

Production is visible everywhere

Nine independent layers, starting with the ledger rule turning coral in every table and a 2px bar across the top of the window. Destructive actions on production ask you to type the name. Most incidents are right-action-wrong-cluster.

Access

Built to WCAG 2.2 AA

Zero contrast failures across every surface, no state encoded by colour alone, a 24px minimum hit target, full keyboard navigation and a command palette that is the real navigation. Verified in Windows high-contrast mode.

Build instructions

The binaries are not code-signed yet. On macOS, right-click the app and choose Open the first time; on Windows, SmartScreen will warn you and you will need More info → Run anyway. That is what an unsigned build from an independent developer looks like, and saying so here is better than letting the operating system say it first. Every release ships a SHA256SUMS.txt so you can check what you downloaded against what CI built.

03

No cluster to point it at?

Kavka's first-run screen offers to start one for you. It runs a single-node Kafka in Docker on localhost:19092, seeds a few topics with records and a consumer group with real lag, and saves a connection called Playground — about thirty seconds, one click.

Kavka does not bundle a broker, and it says so on that screen rather than here only. Apache Kafka is a JVM application: bundling one would mean shipping a Java runtime, and a 300 MB download is precisely the thing this app exists not to be. If you have Docker, the button works. If you do not, you get one honest sentence instead of a button that cannot.

04

Your clusters, in Claude and Cursor

Kavka ships a second binary that speaks the Model Context Protocol over stdio and reads the same connections and the same keychain the app does. Point an assistant at it and it can look at your clusters with exactly the credentials you already trust — nothing listens on a port, and nothing leaves the machine unless your assistant sends it. 

claude mcp add kavka -- "/Applications/Kavka.app/Contents/MacOS/kavka-mcp"

It is read-only until you say otherwise. The two tools that write — produce a record, reset a group's offsets — only exist if the client starts the server with KAVKA_MCP_ALLOW_WRITES=1, and a production connection needs KAVKA_MCP_ALLOW_PROD=1 as well. A connection you marked read-only refuses regardless. There is no delete, no create, no ACL change and no config change over MCP at all.

  • kavka_list_topicsEvery topic, with partitions and replication.
  • kavka_fetch_messagesRecords from a seek point — at most 500.
  • kavka_searchA bounded scan; matches and counts, never a whole topic.
  • kavka_sqlSQL over a bounded scan of one topic.
  • kavka_group_detailOne group's members, offsets and lag.

Session masking rules travel to it. Redactions you configure in the app are stored beside the connection file the server reads, so they apply to what an assistant is handed — not just to what is on your screen. An assistant's context is logged, replayed and sent to somebody else's server, which is exactly why that direction matters.

AGPL-3.0, and what that means for you

The GNU Affero General Public License, version 3. In practice, for the four situations people actually ask about:

Using it
Free, forever, for anything — at home, at work, at a company of any size, against production clusters. No registration, no seat count, no phone-home. Nothing is asked of you.
Modifying it
Go ahead. If you keep the changes to yourself, that is the end of it — the licence only has something to say when you distribute.
Distributing it
If you ship a modified Kavka to anyone, you publish your source under the same licence. This is the clause that means there can be no closed-source fork with the good bits behind a paywall, which is the failure mode this project exists in response to.
Hosting it
The "Affero" part: offering a modified Kavka as a network service counts as distributing it. Kavka is a desktop app with no server component, so this is unlikely to come up — it is here so it cannot be routed around later.
